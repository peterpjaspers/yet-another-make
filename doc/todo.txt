Bugs
- create test_yam dir and build it. Then rename dir project to project1 and run yam.
  Expected result: build passes, actual result: build fails because stale output
  files in dir project1.
  Beta build: yamServer was observing the repository when the renaming  took place. 
  Yam detects that project was renamed to project1. It can then rename the mirror
  of project to project1. However, renaming a node is not trivial.
  Alpha build: Yam will remove mirror of project and add mirror of
  project1 and will see no relation between these 2 events. Perhaps heuristics
  can be used to detect that project1 is a rename of project. In that case
  Yam can delete the stale output files. Should only be deleted on user confirm.
  Try to solve this or accept and explain in the manual?

- Removal of temp dir by CommandNode succeeds according to std::filesystem::remove_all
  but in reality most of these temp dirs stay in existence.
  Running a build with threadpool of size 1 fixes this problem.
  A problem in Windows or in std::filesystem?
  Workaround: serialize remove_all calls
  Problem: this also does not remove all temp dirs.
  Workaround: delete temp dirs at start of each build.

- Changing yamConfig\repoName.txt is not handled: requires creation of new home
  repository node. Can be handled as clearing everything followed by intial build.

- AccessMonitorTest.compareWithMSBuildTracker behaves differently when ran from test
  explorer versus directly from cmd shell. In the latter case duplicate paths 
  with mixed casing (C:\ and c:\) are detected with different access modes.
  This causes the test to fail.
  Using std::filesytem::canonical does not work because this only works for existing
  files. weakly_canonical could fix this but it does not work according to spec: it
  returns error and empty path for e.g. c:\d1\f2 where C:\D1 exists and f2 does not.
  In this case it should have returned error and C:\D1\f2.

- Running yam --noServer while server is running will result in server to cache 
  wrong version of buildstate. Server not designed to deal with changes in buildstate
  file made by other processes.
  Quick fix: shutdown server when running --noServer.

- MonitoredProcessWin32 passes the entire environment to child processes. 
  This was done during the work to build yam with yam. It was done as a hack to 
  work-around the dependency of the MS compiler and linker on the many
  environment variables in the MS development environment.
  In the final solution these environment variables must be defined as part
  of the build rules. The hack was choosen because the current buildrule syntax does 
  not support variables and because a new buildrule language is being implemented.

- yam creates group hierachy of output files. Hierarchy
  mirrors the directory tree in which outputs are stored.
  E.g. outputs are a/O1, a/O2, a/b/c/O3. 
  Output groups <a> contains O1, O2 and <b>, <b> contains <c>, 
  <c> contains O3.
  yam <b>/** builds all outputs in <b> recursively. Same would happen
  for yam b/**. 
  <b>/** is kind of O(N) where N is nr of elements below <b>
  b/** is O(N), where N is nr of dirty generated file nodes in buildstate.
  yam <b>/<c>/O3 is O(N) where N is nr of elements in <b> and in <c>
